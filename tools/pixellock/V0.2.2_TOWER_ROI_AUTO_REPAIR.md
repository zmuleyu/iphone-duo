# PixelLock v0.2.2 — Tower ROI Lock + Auto FAIL/Repair

This increment changes only the **Geometry-Locked A → B backend closure**. It does not tune or judge final art direction.

## 1. Immutable Tower ROI Lock

At `prepare`, PixelLock detects Tokyo Tower **only in Geometry Source A**, freezes the detected bounding region, adds fixed padding, and stores an immutable ROI reference. Every later B attempt is measured against this same A-derived ROI; B is never allowed to redefine the lock area.

New prepare artifacts:

- `qc/tower_roi_A.png`
- `qc/tower_roi_mask_A.png`
- `qc/tower_roi_edges_A.png`
- `qc/tower_edge_template_A.png` (full-size frozen tower-edge template)

The project state stores `restyle.tower_roi_lock` with the frozen ROI, reference bbox, reference center, reference area, and SHA-256 fingerprints. If Geometry Source A changes after Prepare, generation/repair is rejected until Prepare is run again.

## 2. Tower position hard gate

Tower translation is estimated from **A-only structural tower edges** against the candidate B edge map inside the frozen ROI.

Default rules:

- `|dx| <= 4 px`
- `|dy| <= 4 px`
- `|dx| > 8 px` or `|dy| > 8 px` = hard failure
- hitting the ±16 px registration search boundary = hard failure

This avoids relying only on a full-frame correlation that can be confused by newly introduced poster/style edges.

## 3. Tower shape hard gate

After best translation alignment, PixelLock evaluates:

- A tower structural-edge retention
- locked-ROI tower mask IoU
- tower bbox side deltas
- tower mask area-ratio drift

The shape gate is independent from the position gate, so the report can distinguish **"tower moved"** from **"tower was redrawn/rescaled"**.

## 4. Automatic FAIL → Repair loop

Restyle generation can now run as a backend closed loop:

`Generate B → hard QC → FAIL → measured repair prompt → regenerate from A → QC → ...`

The default run budget is 3 attempts. All failed and successful attempts remain in `restyle.attempts` with their QC reports.

`GenerateRequest` now supports:

- `auto_qc: true`
- `auto_repair: true`
- `max_attempts: 3`

For restyle projects, the browser's Generate action enables this loop by default. Manual `/restyle/validate` and `/restyle/repair` remain available.

If the run budget is exhausted, the state becomes `repair_exhausted`. Export remains blocked unless geometry QC passes.

## 5. Measured repair instructions

When Tower ROI Lock fails, the repair prompt now carries measured displacement, e.g.:

- detected `dx=+9 px`, `dy=-8 px`
- return tower approximately `9 px left`, `8 px down`
- reuse A's exact tower silhouette/bbox/height/width/lattice geometry
- never move surrounding buildings to compensate

The next candidate is still regenerated from **Geometry Source A**, not from the failed B.

## 6. QC artifact per attempt

Each validation now emits:

- `qc/tower_roi_overlay_XX.png`
- `qc/qc_report_XX.json`

The overlay is a diagnostic A/B crop only; it is not part of the final visual output.

## 7. Preset defaults

`presets/tokyo_ab_restyle.json` adds `geometry_lock.tower_roi_lock`:

- padding: 24 px
- structural edge band: 8 px
- edge tolerance: 4 px
- translation search: ±16 px
- position soft limit: 4 px per axis
- position hard limit: 8 px per axis
- aligned structural retention >= 0.78
- mask IoU >= 0.72
- bbox side delta <= 10 px
- area-ratio delta <= 0.18

Global skyline/building hard gates from v0.2.1 remain active after the Tower ROI gate.

## 8. Verification

Offline deterministic tests cover:

- immutable A-derived ROI artifacts
- normal local restyle PASS
- 12 px / -7 px injected translation hard-FAIL
- automatic first-attempt FAIL followed by second-attempt repair PASS
- attempt history preservation

No final-art adjustment is included in this version.
