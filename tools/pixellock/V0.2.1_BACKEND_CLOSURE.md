# PixelLock Image Pipeline v0.2.1 — Geometry-Locked Restyle Backend Closure

This increment deliberately focuses on the backend workflow, not final image art.

## Contract

- **Geometry Source A** is the only geometry authority.
- **Style Reference B** is stored separately and can be supplied to the image provider as style-only input.
- Every generated B is versioned as `B_candidate_XX.png`.
- A candidate cannot become `restyle_B_geometry_pass.png` until hard geometry QC passes.
- Failed candidates keep their QC report and can enter bounded automatic repair (maximum 3 attempts by default).

## Prepare artifacts

`POST /api/projects/{pid}/restyle/prepare` creates:

- `qc/edge_map_A.png`
- `qc/tower_mask_A.png`
- `qc/skyline_mask_A.png`
- `qc/structure_overlay_A.png`
- API-sized edit input + mask without resizing A

## Restyle endpoints

- `POST /api/projects/{pid}/restyle/style-reference`
- `POST /api/projects/{pid}/restyle/prepare`
- `POST /api/projects/{pid}/restyle/generate`
- `POST /api/projects/{pid}/restyle/validate`
- `POST /api/projects/{pid}/restyle/repair`

Legacy `/prepare`, `/generate`, and `/validate` routes now delegate to the same restyle backend when the project workflow is `restyle`.

## Hard geometry QC

- exact dimensions
- Tokyo Tower phase-correlation anchor shift: target <= 4 px
- Tokyo Tower proxy-mask IoU
- Tokyo Tower bbox IoU
- anchor structural-edge F1
- skyline structural-edge F1
- skyline silhouette-mask IoU

Any hard geometry failure prevents acceptance/export.

## Style QC

Heuristic checks are reported separately:

- sky redness
- building darkness
- tower warmth
- tower luminance dominance

They are advisory by default (`hard_gate=false`) so style tuning does not weaken the geometry gate.

## Repair

`/restyle/repair` converts failed QC fields into a stronger repair prompt and retries while keeping A as the geometry source. Each candidate and QC result is retained in project state for auditability.
